# Stage map

| # | Stage | Agent (model) | Where it runs | Artifact | Check (who decides) | On failure |
|---|---|---|---|---|---|---|
| 1 | Requirements | Analyst (Opus 5.5) with the A1 skill | build job | `spec.md` | Code: every acceptance criterion has an ID `AC-FR-xxx-yy` and Given/When/Then; no requirement is `BLOCKED_ON_CLARIFICATION`. LLM judge (Haiku 5.5) marks each AC testable / not testable. The orchestrator decides pass/fail. | One retry with the check output. Still failing (or blocked): post the open questions on the issue, write the reason in `spec.md`, stop. |
| 2 | Design | Analyst (Opus 5.5) with `ARCHITECTURE.md` | build job | `design.md` | Code: a "Change plan" table exists; every listed file exists (or is marked `new`); every listed function/class exists in that file (AST), or is marked `new`. Orchestrator decides. | One retry with the check output, then stop. |
| 3 | Implementation | Implementer (Opus 5.5) | build job, branch worktree | `diff.patch` | Code: diff is non-empty, touches no `.github/` file and no acceptance-test file; `pip install -e .`, `python -m compileall markdown`, `import markdown` succeed. | Retry with the build error (counts against the implementation budget). |
| 4 | Testing | Tester (Opus 5.5), blind to the implementation | build job, clean worktree at base | `test_report.md` | Code: each AC ID has at least one test `test_ac_fr_xxx_yy_*`; the full suite (`python -m unittest discover tests`) passes with the new tests. Orchestrator decides. | Back to stage 3 with the failing output (max 3 implementation attempts per design); after 2 failed attempts, back to stage 2 once; then stop. |
| 5 | Release | none (deterministic job) | release job | `pr.md` + PR link | Code: PR state is `OPEN`; the `ci.yml` run dispatched on the branch concluded `success`. | Write the CI log link into `pr.md`, stop. |
| 6 | Review | Reviewer (Sonnet 5.5), separate job | review job | `review.md` + `verdict.json` | Reviewer's structured verdict (`approve` / `request_changes` + `route`); route job validates it (schema, evidence present). | `route: design` or `route: implementation` re-dispatches the workflow from that stage, at most 2 times. Then stop: a human decides. |
