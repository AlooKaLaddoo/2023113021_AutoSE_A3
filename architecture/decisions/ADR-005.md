# ADR-005: Claude Code CLI with per-role tool lists; GitHub access only in deterministic steps (D5)

**Status:** Proposed (2026-11-24)

## Context

Agents need file and shell tools. GitHub operations (comment, push, open PR) are the riskiest powers in the system. Options are an MCP server (e.g. the GitHub MCP server), the `gh` CLI, or the REST API, and on the agent side the Claude Agent SDK or the Claude Code CLI in headless mode (`claude -p`).

## Decision

- Agents run as **headless Claude Code** (`claude -p --output-format stream-json`). The orchestrator passes, per role, `--tools` (which built-in tools exist at all), `--allowedTools` (which are pre-approved), `--permission-mode dontAsk` (anything else is denied, not prompted), `--model`, `--append-system-prompt-file`, and `--max-budget-usd`. No MCP servers are loaded (`--strict-mcp-config`), so no web tools exist.
- **No agent gets a GitHub tool or token.** `actions/checkout` runs with `persist-credentials: false`; `GITHUB_TOKEN` is passed only to the deterministic steps that need it (fetching the issue, `git push`, `gh pr create`, `gh pr review`, `gh workflow run`), all via the `gh` CLI.
- `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` removes credentials from the environment of every command an agent runs.
- After every editing agent, the orchestrator enforces a file allowlist in code (e.g. the Tester may only add `tests/test_autose_issue_N.py`; the Implementer may not touch `.github/` or the acceptance tests). Out-of-scope changes are reverted and logged.

## Alternatives considered

- **GitHub MCP server for every agent.** Convenient, but gives the agents the power to comment, push or merge; a prompt injection could then act on GitHub.
- **Claude Agent SDK (Python).** Same harness with a Python API; the CLI was chosen because the same flags can be run by hand to reproduce one agent call.
- **Permission rules only (no code allowlist).** Path rules in permission settings are easy to get wrong; a `git diff --name-only` check after the agent is simple and certain.

## Consequences

- Good: a compromised or confused agent can at worst produce a bad diff, which then has to pass checks, CI, the reviewer and a human.
- Good: each role's power is visible in one place (`config.json`).
- Bad: Bash with `python -m unittest` still runs code the agent wrote, i.e. arbitrary code inside the runner. This is contained by the scrubbed environment, the missing token and the throw-away runner, not prevented.
