# ADR-003: Hand-offs are files, never conversations (D3)

**Status:** Proposed (2026-11-24)

## Context

Each agent starts with an empty context. What we put in decides what it can know and what it can be biased by. Passing whole transcripts carries the previous agent's mistakes and rationalisations forward; passing too little forces each agent to rediscover everything.

## Decision

Every hand-off is a **named markdown artifact** plus repository access. Nobody receives another agent's transcript.

| Receiver | Gets | Deliberately does not get |
|---|---|---|
| Analyst, stage 1 | issue title/body/author wrapped as untrusted data, repo (read-only), A1 skill | nothing else exists yet |
| Analyst, stage 2 | `spec.md`, `ARCHITECTURE.md`, repo; on loop-back the reviewer's `review.md` or the failing-test summary | the issue text again (the spec is the contract) |
| Implementer | `spec.md`, `design.md`, repo; on retry the failing test output; on loop-back `review.md` | the Tester's reasoning; the Analyst's transcript |
| Tester | `spec.md`, clean checkout of the base commit | `design.md`, the diff, the implementer's output |
| Reviewer | issue text, `git diff base...head`, repo at the PR head | `spec.md`, `design.md`, `test_report.md`, any transcript (ADR-008) |

The orchestrator writes the artifacts; agents return their artifact as their final message (Analyst) or as files in the working tree (Implementer, Tester), which the orchestrator turns into a diff.

## Alternatives considered

- **Full transcripts / shared session.** Maximum context, but bias travels with it, and the reviewer would no longer be independent.
- **Short LLM-written summaries.** Smaller, but a summary drops exactly the details a later stage needs (acceptance-criteria wording), and adds an unchecked LLM step.

## Consequences

- Good: every hand-off is inspectable on GitHub (artifacts) and can be checked by code.
- Good: the Tester's blindness to the design is what makes ADR-001 work.
- Bad: each agent re-explores the repository (more tokens).
- Bad: if `spec.md` is wrong, everything downstream is wrong; only the reviewer (who reads the issue, not the spec) can catch that.
