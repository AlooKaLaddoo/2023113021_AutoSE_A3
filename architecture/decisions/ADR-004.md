# ADR-004: State lives in workflow artifacts, the PR branch and one state comment (D4)

**Status:** Accepted (2026-11-24, confirmed by the runs in `results/runs.md`). Proposed 2026-11-24.

**Amended 2026-11-24** (names only, decision unchanged): the original text named the artifacts `autose-issue-N-rR-<job>`; the implementation uses `autose-build-N`, `autose-release-N`, `autose-review-N`. Since commit `6b5f4a3`, experiment variants use their own branch `autose/issue-N-<variant>` (and so their own PR), so variant runs never touch the main design's branch.

## Context

State is needed (a) between stages inside a run, (b) between jobs of a run, and (c) between runs (review rounds, restarts). Options are files on the PR branch, workflow artifacts, the Actions cache, and issue/PR comments. A constraint from ADR-008: anything committed to the PR branch is part of the diff the reviewer sees, so `spec.md` and `design.md` must not be committed there, or the reviewer would read the implementer side's reasoning.

## Decision

| State | Where | Why |
|---|---|---|
| Stage artifacts (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`, `verdict.json`, agent transcripts) | Workflow artifacts `autose-build-N`, `autose-release-N`, `autose-review-N` (`autose-review-prN` for review-only runs) (retention 30 days) | Visible on the run page; not in the PR diff |
| The code change | Branch `autose/issue-N` (`autose/issue-N-<variant>` for experiment variants); each round adds a commit on top | Reviewable, human-mergeable |
| Run index (round, PR number, run ids, stage results) | One issue comment marked `<!-- autose-state -->` with a JSON block plus a human-readable table | Survives across runs; readable by anyone following the issue |

Inside the build job, stages hand over through files in a work directory. Between rounds, the next run downloads the previous run's artifacts (`gh run download <run_id>`), using the run id stored in the state comment.

**Restarts.** Every job is idempotent: re-running `build` recomputes the artifacts (uploads use `overwrite: true`); `release` adds a new commit to the existing branch (never force-pushes) and reuses an open PR; `route` edits the existing state comment rather than adding a new one.

## Alternatives considered

- **Commit artifacts to the branch** (`.autose/`): easy to resume, but leaks spec/design into the reviewer's diff and into the code a human merges.
- **Actions cache:** not meant for state; entries can be evicted at any time.
- **External store (database, gist):** another credential and another place to look.

## Consequences

- Good: everything is on GitHub and linkable from `runs.md`.
- Bad: artifacts expire (30 days). The submission copies the important ones into `results/`.
- Bad: a cancelled build job loses partial in-job progress; the run restarts the round from its first stage.
