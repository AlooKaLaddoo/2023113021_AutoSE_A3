# ADR-010: Maintainers trigger by label or command; one run per issue at a time (D10)

**Status:** Accepted (2026-11-24, confirmed by the runs in `results/runs.md`). Proposed 2026-11-24.

## Context

Runs consume plan usage and open PRs, so only maintainers should start them. Two runs on the same issue (e.g. a label and a comment a second later) would race on the same branch and the same state comment.

## Decision

**Events**

| Event | Condition | Starts |
|---|---|---|
| `issues: labeled` | label is `autose` | full run, round 1 |
| `issue_comment: created` on an issue | body starts with `/autose`, `author_association` in `OWNER`, `MEMBER`, `COLLABORATOR`, author is not a bot | full run, round 1 |
| `issue_comment: created` on a PR | body starts with `/autose review`, same author rule | reviewer only (used for seeded PRs and re-reviews) |
| `workflow_dispatch` | inputs `issue`, `round`, `from_stage`, `mode`, `variant` | used by the route job for review rounds, and by us for experiments |

Adding a label already requires triage access, so the label path is maintainer-only by GitHub's own rules. The `gate` job checks the comment rules and exits early otherwise.

**Concurrency.** `concurrency: group: autose-<issue or PR number>`, `cancel-in-progress: false`: a second run for the same issue waits until the first finishes, and runs on different issues proceed in parallel.

## Alternatives considered

- **`issues: opened` (run on every new issue):** anyone could start a run.
- **`cancel-in-progress: true`:** the newer run wins, but a half-pushed branch from the cancelled run is left behind.
- **Checking permissions through the API (`/collaborators/{user}/permission`):** more exact than `author_association`, one extra API call; `author_association` is sufficient for a personal fork.

## Consequences

- Good: strangers can open issues, but cannot start the bot.
- Bad: GitHub keeps only one *pending* run per concurrency group; a third trigger while one runs and one waits replaces the waiting one.
- Bad: workflows on forks of *our* fork would not get secrets, so external contributors cannot run it (intended).
