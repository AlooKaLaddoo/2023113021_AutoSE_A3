# ADR-011: Agent shell commands run inside Claude Code's sandbox; the orchestrator removes its placeholder files (D5, D9)

**Status:** Accepted (2026-11-24). Supersedes ADR-005.

## Context

ADR-005 assumed that agent shell commands run directly on the runner, contained only by a scrubbed environment and the missing GitHub token, and accepted that "Bash still runs arbitrary code" with no further protection. Two real runs showed that this picture was wrong:

1. **Run [45419585282](https://github.com/AlooKaLaddoo/markdown/actions/runs/45419585282)** (review of seeded PR #6). Claude Code 2.1.331 reports `sandbox_enabled: true`. It *requires* its Bash sandbox (bubblewrap with a socat network proxy) and refuses to run commands outside it. The runner had no `socat`, so every Bash call failed. The reviewer could not run a single test, and said so instead of approving.
2. **Run [45420334361](https://github.com/AlooKaLaddoo/markdown/actions/runs/45420334361)** (issue #3, PR #11). With the sandbox working, it creates empty placeholder files for sensitive paths (`.env*`, `package.json`, `.npmrc`, `yarn.lock`, ...) in the working directory and leaves them there. Our `git add -A` put 17 empty files into the PR. The independent reviewer caught this as a `major` finding.

## Decision

Everything in ADR-005 still holds: per-role `--tools` / `--allowedTools`, `--permission-mode dontAsk`, no MCP servers, no GitHub token for any agent, `persist-credentials: false`, the environment scrub, and code-enforced file allowlists. In addition:

- **Agent shell commands always run in Claude Code's bubblewrap sandbox.** The build and review jobs install `bubblewrap` and `socat` and allow unprivileged user namespaces (`sysctl kernel.apparmor_restrict_unprivileged_userns=0`). Sandboxed commands can write only inside the working directory and have no network access unless a domain is explicitly allowed (none are).
- **Only user-level settings are loaded** (`--setting-sources user`). A `.claude/` directory or `CLAUDE.md` inside a PR therefore cannot reconfigure an agent, and changes to those paths are rejected like changes to `.github/`.
- **The orchestrator removes sandbox placeholders.** Any new, empty, top-level file named like a sandbox placeholder is removed before the diff is taken (`checks.SANDBOX_STUBS`).

## Alternatives considered

- **Turn the sandbox off** (settings `sandbox.enabled: false`): simpler, but it throws away the one control that actually stops agent-written code from reaching the network, which is the main remaining prompt-injection risk in ADR-005.
- **Add the placeholder names to `.gitignore`**: would also work, but changes the product repository for a tooling reason, and does not cover the reviewer's checkout.

## Consequences

- Good: the residual risk that ADR-005 accepted (exfiltration from code the agent runs) is now blocked at the network level, not just reduced.
- Good: the case shows the value of the independent reviewer. It caught a defect introduced by our own pipeline, which no stage check covered.
- Bad: about 20 s extra setup per job, and a dependency on undocumented sandbox behaviour (the placeholder names); a new CLI version could change them. The CLI version is pinned (`CLAUDE_CODE_VERSION`) for that reason.
